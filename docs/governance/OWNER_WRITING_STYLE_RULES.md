# Owner Writing Style Rules

Status: APPROVED
Owner: Mostafa Gad
Scope: All project-generated human-readable content unless an external source must be quoted verbatim.

## No em dash

Do not use the em dash character in any project-authored content.

This applies to, at minimum:

- website copy and UI text;
- Figma copy and annotations;
- prompts and handoff instructions;
- GitHub documentation, issues, pull requests and release notes;
- emails, letters and professional correspondence drafted for the Owner;
- product content, help text and marketing copy;
- reports, CV-related output, proposals and presentation copy.

Use punctuation appropriate to the sentence instead, such as:

- comma;
- colon;
- semicolon;
- parentheses;
- ordinary hyphen where grammatically appropriate;
- or rewrite the sentence.

## Exceptions

The character may remain only when it is part of content that must be preserved exactly, for example:

- a verbatim external quotation;
- a source title or legal text that must not be altered;
- existing machine-generated data where changing it would corrupt the source.

Do not introduce new em dashes into Owner-authored or project-authored text.

## Governance

This is an explicit Owner-approved cross-project writing preference. It does not merge project architectures or Source of Truth boundaries. Each repository should apply the rule independently to its own authored content.
